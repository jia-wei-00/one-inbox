# One Inbox Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a personal Android app that captures chat-app notifications into one local inbox and summarizes unread messages with Claude on demand.

**Architecture:** A `NotificationListenerService` turns chat notifications into plain `NotificationSnapshot`s. A pure `NotificationParser` converts them into `CapturedMessage`s, which are stored in Room. Compose screens (inbox with an app rail, conversation view, catch-up, onboarding, settings) read Room through `InboxRepository`. When Summarize is tapped, `CatchUpRepository` builds a prompt from the unread messages, calls Claude through the official Anthropic Java SDK with structured JSON output, and caches the result in DataStore.

**Tech Stack:** Kotlin 2.2.21, AGP 8.13.2, Gradle 8.13, Jetpack Compose (BOM 2026.06.00) + Material 3, Navigation Compose 2.9.8, Hilt 2.58 (KSP 2.2.21-2.0.5), Room (latest stable 2.8.x, KSP), DataStore Preferences 1.2.1, kotlinx.serialization 1.9.0, coroutines 1.10.2, `com.anthropic:anthropic-java:2.34.0`. Tests: JUnit 4.13.2, Robolectric (latest stable, run at `@Config(sdk = [35])`), kotlinx-coroutines-test. Versions are copied from `C:\vscode\expense-tracker-kotlin\gradle\libs.versions.toml`.

**Spec:** `docs/superpowers/specs/2026-11-21-one-inbox-design.md`

## Global Constraints

- Project root: `C:\vscode\one-inbox`. Package and applicationId: `one.inbox`. `minSdk = 31`, `targetSdk = 36`, `compileSdk = 36`, Java/JVM target 17.
- Single user, single device (Xiaomi 15T Pro, HyperOS). Sideloaded via Android Studio or adb. No Play Store, backend, Supabase or Firebase.
- Messages come in **only** through notification capture. No logins, bridges or scraping.
- Message content leaves the phone **only** when the owner taps Summarize. No background or scheduled AI calls.
- Claude model `claude-opus-5-5`, effort `LOW`, `maxTokens = 16000`, structured JSON output, server-side refusal fallback `fallbacks: "default"` with beta header `server-side-fallback-2026-07-01`.
- The API key is entered in Settings and stored encrypted with Android Keystore. It is never in `BuildConfig`, logs or git.
- Read-only. Never post, reply to or dismiss the source apps' notifications.
- Unread means "not yet seen in One Inbox". The owner's own messages are never unread.
- Capture failure must be visible: a health banner on the inbox (spec, "Reliability").
- Mirror `expense-tracker-kotlin` conventions: version catalog, Hilt, `feature/`-style packages, secrets only in git-ignored `local.properties` (here: just `sdk.dir`).

## Review Focus

1. **Blank or system notifications** ("Checking for new messages", typing indicators, call notifications, empty text): never stored as empty messages. → Task 2 test `blankAndSystemNotificationsProduceNothing`.
2. **Chinese/Malay text and emoji** (the owner is in Malaysia): survive parsing, storage, the prompt and JSON parsing unchanged. → Task 2 `cjkAndEmojiPreserved`, Task 6 `cjkAndEmojiRoundTrip`.
3. **Summarize fails** (no network, 401 bad key, refusal): a clear message is shown, nothing is marked read, and the previous summary is kept. → Task 7 `failureLeavesUnreadAndPreviousSummary`.
4. **A group or contact is renamed**: same conversation (shortcutId-based key), title updated to the newest. → Task 3 `renamedConversationKeepsKeyAndUpdatesTitle`.
5. **MessagingStyle message with timestamp 0**, which some apps send: falls back to the notification's `postTime` so ordering stays sane. → Task 2 `zeroTimestampFallsBackToPostTime`.

### Task 2: Notification parser

**Files:**
- Create: `capture/NotificationSnapshot.kt`, `capture/CapturedMessage.kt`, `capture/NotificationParser.kt`
- Test: `app/src/test/java/one/inbox/capture/NotificationParserTest.kt`

**Interfaces:**
- Produces:
```kotlin
data class SnapshotMessage(val sender: String?, val text: String?, val timestamp: Long, val mimeType: String? = null) // sender null = the owner
data class NotificationSnapshot(
    val packageName: String, val notificationKey: String, val userId: Int, val postTime: Long,
    val shortcutId: String?, val isGroupSummary: Boolean, val isOngoing: Boolean, val category: String?,
    val title: String?, val text: String?, val conversationTitle: String?, val isGroupConversation: Boolean,
    val selfName: String?, val messages: List<SnapshotMessage>)
data class CapturedMessage(
    val conversationKey: String, val packageName: String, val conversationTitle: String, val isGroup: Boolean,
    val sender: String, val isFromMe: Boolean, val text: String, val timestamp: Long, val dedupeKey: String)
object NotificationParser {
    fun parse(s: NotificationSnapshot, allowed: Set<String>): List<CapturedMessage>
    fun conversationKey(s: NotificationSnapshot): String
}
```

Rules, all decided here:
- Return empty if the package isn't in `allowed`, `isGroupSummary`, `isOngoing`, or `category` is `call`/`progress`/`service`/`transport`.
- `conversationKey = "${userId}|${packageName}|${shortcutId ?: conversationTitle ?: title ?: notificationKey}"`. Including `userId` keeps Xiaomi Dual Apps separate.
- Conversation title: `conversationTitle ?: title ?: displayName`. `isGroup = isGroupConversation`.
- **MessagingStyle path** (`messages` non-empty): one `CapturedMessage` per message. `isFromMe = sender == null || sender == selfName`. Sender shown as `"You"` when `isFromMe`. A `timestamp <= 0` becomes `postTime`. Blank text with an `image/*` mime type becomes `"📷 Photo"`, with `audio/*` becomes `"🎤 Voice message"`, with any other mime type becomes `"📎 Attachment"`. Blank text with no mime type is skipped.
- **Fallback path** (no messages): one message, sender = `title`, text = `text`, timestamp = `postTime`. Skip if text is blank.
- Both paths skip pure placeholders matching `(?i)^\d+ new messages?( from \d+ chats?)?$` or `(?i)^checking for new messages.*`.
- `dedupeKey` = SHA-256 hex of `"$conversationKey|$sender|$timestamp|$text"` on the MessagingStyle path, and of `"$conversationKey|$sender|$text"` on the fallback path. The fallback has no stable timestamp across reposts, so the same text from the same sender in a fallback-only app collapses into one message. That's accepted.

- Produces: `object SnapshotExtractor { fun from(sbn: StatusBarNotification): NotificationSnapshot }`, and `@AndroidEntryPoint class InboxListenerService : NotificationListenerService()`.

`SnapshotExtractor` reads `NotificationCompat.MessagingStyle.extractMessagingStyleFromNotification(n)` for messages (`person?.name`, `text`, `timestamp`, `dataMimeType`), `conversationTitle`, `isGroupConversation` and `user.name` (selfName). Service behavior:
- `onNotificationPosted`: extract → parse with the current allowlist → `save` on a `SupervisorJob` + `Dispatchers.IO` scope. Catch and log exceptions; never crash the listener.
- `onListenerConnected`: set `ListenerState.connected = true`, then backfill by parsing and saving every `activeNotifications` entry.
- After every post/removal and on connect, re-parse `activeNotifications` with the current allowlist and publish the result to `ListenerState.activeMessages` (used by the health check).
- `onListenerDisconnected`: set `connected = false`, then call `requestRebind(ComponentName(this, InboxListenerService::class.java))`.

- Produces:
```kotlin
interface Summarizer { suspend fun summarize(prompt: String, apiKey: String): SummarizeResult }
sealed interface SummarizeResult { data class Json(val text: String); data object Refused; data class Failed(val message: String) }
class ClaudeSummarizer @Inject constructor() : Summarizer
@Serializable data class StoredCatchUp(val catchUp: CatchUp, val generatedAt: Long, val includedIds: List<Long>,
    val unreadCount: Int, val appCount: Int, val droppedCount: Int)
sealed interface CatchUpOutcome { data class Done(val stored: StoredCatchUp); data object NoUnread; data object NoApiKey;
    data object Refused; data class Failed(val message: String) }
class CatchUpRepository @Inject constructor(...) {
    val latest: Flow<StoredCatchUp?>
    val newSinceCount: Flow<Int>          // unread incoming messages whose id is not in latest.includedIds
    suspend fun run(): CatchUpOutcome
    suspend fun markSummaryRead()         // markRead(latest.includedIds) only
}
```
`ClaudeSummarizer` uses `AnthropicOkHttpClient.builder().apiKey(apiKey).build()` and `MessageCreateParams.builder().model("claude-opus-5-5").maxTokens(16000L).system(SYSTEM_PROMPT).addUserMessage(prompt).outputConfig(OutputConfig.builder().effort(OutputConfig.Effort.LOW).format(JsonOutputFormat …manual schema…).build()).putAdditionalHeader("anthropic-beta", "server-side-fallback-2026-07-01").putAdditionalBodyProperty("fallbacks", JsonValue.from("default"))`. Run it on `Dispatchers.IO`. Map `stopReason == refusal` → `Refused`. Join the text blocks → `Json`. Map SDK exceptions → `Failed("Invalid API key")` for 401, `Failed("No connection")` for IO, otherwise `Failed(message)`. Schema: an object with required arrays `needs_reply`, `worth_knowing`, `low_priority`, each of objects `{conversation_id: string, summary: string}`, all with `additionalProperties: false`.

`SYSTEM_PROMPT` (exact copy):
```
You summarize a person's unread chat messages from several apps so they can catch up in one glance.
Sort every conversation into exactly one bucket:
```
